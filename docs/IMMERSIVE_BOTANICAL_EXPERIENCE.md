# VIRIDEXA · 沉浸式植物探索体验验收

执行日期：2026-10-28。本轮直接修改 Vue、样式与已授权影像派生文件；未修改科学数据模型、生产账户、发布决定或受保护原始文件；未推送 GitHub。

## 实际审计与设计方向

已打开原首页、浏览、银杏详情、图谱、技术看板，并记录改造前截图。生产助手与实验台需要登录，原样记录其登录入口；改造后在独立 MySQL 与明确标注的自动化账户中验证专业页面，不把这些截图当作生产真实用户审核。

原有问题：首屏检索与研究术语过早出现；各模块比植物本身更显眼；详情字段密集；高级筛选占据默认阅读路径；手机图文节奏不足。保留原浅色品牌、安全边界及专业功能，通过编辑式图文、留白与渐进披露改变第一印象。

参考 [Kew](https://www.kew.org/) 的自然体验与科学故事层次，以及 [Google Arts & Culture](https://artsandculture.google.com/) 的主题漫游与细节探索。只借鉴叙事节奏，未复制其版式代码或素材。

## 实际实现

- `/`：全幅银杏影像、用户指定标题与两项操作；错落植物图文、近看细节、关系探索、科学幕后、继续探索，六段不同布局。第一屏无数据库指标和 Java 技术栈。
- `/explore`：画廊 / 名称列表、原分页与名称搜索、可折叠组合筛选、快速预览。精选读取真实目录 2、9445、30610，按真实 ID 去重；不将同名记录合成物种。
- 叶片 / 花朵 / 树木入口使用现有 identify 服务查询，有真实匹配才出现。首屏之外接近视口时加载；顺序查询避免三次竞争性扫描触发 503，失败允许重试。检索限服务端首批 1000 条来源；页面最多展示 24 条，明确不代表全库覆盖。源学名尚无目录关联时，只提供同名检索与候选证据入口。
- `/plants/:id`：影像与名字优先；真实外观值、名称、分类、来源、深入研究依次呈现。原始字段和研究上下文保留于折叠区；每个特征可回到候选图谱。未知字段保持原文，不推断用途、分布或故事。
- `/knowledge-graph`：默认公开 `plant:2`，本轮实际返回5个节点、4条关系，仅按需有限一跳；普通界面收起筛选和原始属性，保留文本替代、来源、专业筛选及管理员权限。
- `/assistant`：展示“问问植序”、生活化问题、默认折叠“查看探索过程”、折叠记录属性；领域检索模式明确显示。支持详情携带 plantId，服务端仍校验权限；没有接入真实模型或增加写工具。
- `/technology`：以“每一条知识，都有根。”讲述出处；架构技术栈可展开。来源、三管线、工程测试、限制和安全状态继续完整展示。
- 统一导航改为植物画廊、漫游关系、问问植序、深入研究、幕后技术。科研实验台、审核、认证逻辑保留，不建立平行系统。

核心文件：`apps/web/src/views/{HomeView,AtlasView,PlantDetailView,KnowledgeGraphView,AssistantView,TechnologyView}.vue`、`components/{AppShell,BotanicalCard,BotanicalImage,DiscoveryPaths}.vue`、`ui/discovery.ts`、`styles/immersive.css`。

## 图像、真实性和版权

仅使用既有 3 个严格物种映射：Dan Keck 的银杏 CC0 照片、USDA ARS 的 Camellia oleifera 公有领域照片、F. M. Blanco 的 Jatropha curcas 公有领域历史图版。后者明确表示为图版。缺少中文名的真实目录继续显示学名；没有图片的植物明确显示无图，不套用其他物种影像。来源文档见 `UI_ASSET_PROVENANCE.md`。

从仓库内已保留摄影原件生成 384 / 640 / 960px WebP 共 9 个派生资源，未读取后写回保护目录。共享图片组件使用 srcset、sizes、实际宽高、异步解码、首屏高优先级与下方懒加载。响应式清单见 `reports/immersive/responsive-images.json`。未添加动画库、WebGL、外部字体或视频。

原有首页 / 列表 / 详情模板已替换，复用现有 UI 图标、状态标签、通知、领域 API、Pinia、上下文和权限组件。旧科研功能未删除；本轮没有为了清理 CSS 冒险删除仍被历史页面使用的共享规则。

## 构建与性能

冷缓存本地各条件 3 次导航；桌面 1440×1000，手机 375×812、CPU 4×、150ms 延迟、下行 200000B/s。通过 CDP Trace 记录首屏与快捷搜索交互，没有用单次 Lighthouse 分数冒充生产性能。

| 条件 | LCP 中位 ms | CLS 中位 | 实验交互候选 ms | 到交互结束已收字节 |
|---|---:|---:|---:|---:|
| 桌面 · baseline | 462.03 (2 个有效样本) | 0.0 | 471.24 | 485,322 |
| 手机慢网 / CPU 4× · baseline | 1092.68 (3 个有效样本) | 0.0 | 236.14 | 264,337 |
| 桌面 · after | 299.345 (2 个有效样本) | 0.0 | 503.07 | 357,310 |
| 手机慢网 / CPU 4× · after | 1056.57 (3 个有效样本) | 0.0 | 244.6 | 138,961 |

改造后桌面一次在用户交互前未产生 LCP 候选，故该项仅 2 个有效样本；其余 3 个。交互记录是实验室候选而非真实用户 INP：桌面约 471→503ms、手机约 236→245ms，有波动，仍值得继续优化快捷搜索，不能宣称交互全面提升。堆内存未强制 GC，手机采样有波动，不能据此认定泄漏或收益。资源窗口不是整页完成的固定时刻，字节数仅描述本次观测。

构建总产物 1,724,823 → 2,188,650 B；JS/CSS 1,317,940 → 1,349,615 B。总量主要因新增响应式图片变大，浏览器按尺寸择一下载，不能将磁盘总量当首屏流量。核心入口约 79KB；Cytoscape 约 457KB、ECharts 约 507KB 仍为独立延迟块，首页不加载图引擎。ECharts 500KB 警告仍如实保留。

## 限制与后续

- 仅 3 个获授权图像映射，丰富的物种影像库尚未建立；不自动盗取或错配照片。
- 很多来源描述仍为英文原文，中文翻译和植物故事尚需可靠来源，不能为视觉效果编造。
- 外观入口受现有首批来源检索覆盖限制，顺序读取约数秒；图谱大来源展开仍存在前一轮记录的延迟，本轮没有声称解决其 SQL 瓶颈。
- 无真实 LLM Key，无真实模型联调；公开账户可自行注册但生产本轮未创建。正式事实为0不阻止来源浏览，也没有因展示而虚构具名确认。
- 未执行公网部署、第三方压测或正式用户调研。没有新增图数据库、向量数据库或其他基础服务。

隔离浏览器代理、测试 API 进程、临时 MySQL schema 与专用数据库身份已清理；生产服务保持运行。完整的技术浏览截图均标明隔离用途。
