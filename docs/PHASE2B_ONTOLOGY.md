# Phase 2B ontology projection

`lexical-vocabulary-v1` is a deterministic exact-term vocabulary. Projection retains source-native identifiers together with their originating namespace, including accepted-taxon references, source taxonomic labels and ranks, Chinese names only when supplied, trait source terms, and lipid kind/unit/basis/analyte. Family and genus are populated only from explicit ranked classification entries or a reproducible chain of native parent IDs found among source candidates. Trait values outside the listed vocabulary remain in `source_term` with a null concept; there is no fuzzy or nearest-term matching. Chinese names carry `SOURCE_REPORTED_PENDING` and are not presented as verified.

The `project(pipeline, normalized, raw=None)` function returns `(projection, mapping_state, coverage)` and performs no database writes. Held candidates remain `UNMAPPABLE_SOURCE` with raw payload retained. Coverage reports source, identifiers, parent, family, genus, Chinese name, traits, and lipid basis separately; `SOURCE_PRESENT` does not mean complete ontology coverage. The CLI reads candidates from `scientific_candidate`; `--apply` uses batched insert-only writes to `ontology_projection`, which must be created and granted by the parent migration. Existing checksum conflicts prevent a successful apply report. A projection is descriptive mapping output and never an approval decision.

Vocabulary mappings live in `scripts/pipeline/ontology.py`. Focused behavior tests are in `tests/test_ontology.py`. The actual-source coverage report is intentionally generated by the dry-run CLI after the parent migration's database access is ready.
