# Phase 7S API surface and resource audit

## Current state after Phase 7S protection changes

Earlier audit findings have changed. The general MyBatis timeout remains 5s, while the separate review JDBC pool now sets an 8s statement timeout (ReviewStore.java:17-24); account JDBC also has 8s. Do not carry forward the prior concern that review JDBC has no explicit statement timeout. `/api/v1/security/meta` is now public and no-store (SecurityMetadataController.java:7). API docs are now ADMIN-only (SecurityConfig.java:42), including local mode. `/api/v1/admin/science/catalog` now has ADMIN-only catalog list/detail and decision routes (CatalogReleaseController.java:10-16).

Request filters enforce a 32 KiB cap on POST/PUT/PATCH API bodies including chunked bodies and reject non-JSON declared content types (RequestSizeFilter.java:5-15). Filter order places client IP normalization at highest precedence +5 and body limiting at +10; Spring Security then applies route authorization. RetryAfterFilter supplies a default Retry-After on 429 responses. The size filter allows a missing Content-Type through its own check; downstream JSON binding still governs body parsing. Nginx overwrites forwarding headers and clears `Forwarded` (proxy-common.conf:3-14); the API trusts its private client-IP/proto headers only when immediate peer matches configured CIDR, and accepts only literal IP text (ClientIpFilter.java:10-23). Production compose pins that trust to `172.30.0.10/32`; verify actual container/network peer address on deployment.

Turnstile is disabled by default for local compose and enabled with required production credentials, hostnames, and proxy CIDR in `compose.production.yaml:16-21`. With disabled mode, registration has no challenge; login risk and hard throttling still track failed attempts (after 3 account or 10 IP failures); failures are capped at 12/account, 60/IP per 10 minutes. With enabled mode, registration always requires a valid `register` action token; login requires it after threshold, and verifies any supplied token. The verifier fails closed on missing token, failed Siteverify, hostname/action mismatch, or challenge timestamp outside -300/+30 seconds; timeout is bounded and verifier concurrency is two (`TurnstileVerifier.java:11-19`, `LoginProtection.java:14-19`). Official Cloudflare test Siteverify success responses include `challenge_ts` but omit `action`, while this verifier strictly requires both. That means dummy test credentials may produce rejection even when Siteverify says success; production must use real credentials and verify action/hostname/timestamp claims. This is safe failure, but should be represented as an expected test-mode limitation, not a passing end-to-end challenge.

Security headers are set by Nginx: nosniff, DENY framing, referrer and permissions policy, CSP with Cloudflare Turnstile origins, and HSTS only when the forwarded scheme is HTTPS (`security-headers.conf:1-6`, `web.conf:3`).

Scope: current API source in `apps/api/src/main/java`, runtime config in `application.yml`, compose health wiring, and ingestion CLI entry points. Route authorization is established by `SecurityConfig`; method-level annotations add restrictions for admin actions. No password-reset route or implementation exists in the inspected controllers.

## Controls verified

- Security uses `IF_REQUIRED` server sessions, disabled form/basic auth, JSON 401/403 handlers, method security, and deny-by-default (`SecurityConfig.java:23-45`). CORS is a single configured origin, GET/POST/OPTIONS, explicit headers, credentials disabled (`:51-62`). This fits the current same-origin/session design only if deployed origin and cookie settings are aligned. Production must set `SESSION_COOKIE_SECURE=true`; default false is a deployment risk. CSRF is enabled by Spring defaults and token endpoint is exposed; login rotates session ID and clears prior agent owner and CSRF token (`SessionAuthentication.java:10-13`).
- Public registration/login have email+field bounds, unknown JSON field rejection, redacted record `toString`, in-flight semaphore of 2, and account rate limiter (`AccountController.java:18-28`). Account DB writer pool is size 2, connection timeout 5s and query timeout 8s (`AccountStore.java:11`). Check limiter's in-memory scope before horizontally scaling.
- Agent is authenticated to run, capped by config validation at 3 model calls, 6 tool calls, 2 concurrent, 90s total, 15s/tool, 30s/model, 24k input chars, 1200 output tokens; defaults are lower (3/6/2, 30s total, 5s tool, 12s model). Daily request/token quotas default 20/30k user, 200/300k global. Quota file is local runtime JSON (`AgentQuota.java:18-30`), so multi-replica quotas are not shared. Agent tools whitelist output, constrain tool arguments and cap result sizes (`ResearchTools.java:32-80`).
- MyBatis statement timeout is 5s (`application.yml:32-35`). Workbench and graph service transactions have 10s timeout (`WorkbenchService.java:18`, `GraphService.java:15`). Account and dedicated review JDBC pools each set explicit 8s query timeout (`AccountStore.java:11`, `ReviewStore.java:17-24`). The primary read-only Spring JdbcTemplate is configured with `spring.jdbc.template.query-timeout: 5s`; a real MySQL SLEEP timeout and subsequent SELECT verify timeout and connection reuse.
- Public plant search bounds query length to 120 and page size 1–50 (`PlantController.java:25-34`). Graph service validates search/filter/cursor/depth and caps page sizes (inspect `GraphService.java`); workbench service validates bounded filters/pagination and transaction timeouts. Scientific endpoints accept many unannotated string/integer parameters; service-level validation and mapper SQL limits exist, but bound coverage is uneven. A new QueryBoundsFilter limits GET parameter count/length, q/query to 120, cursor to 2048 and global limit to 100; existing smaller domain limits still apply. Unknown identification concepts retain their original domain semantics. Public query abuse remains a resource-exhaustion surface even though SQL is parameterized and result limits exist.
- Evidence preview is ADMIN-only; it checks permitted license and verified integrity, verifies the path/hash through `EvidenceIntegrity`, allows PDF/PNG/JPEG only, caps at 20 MiB, and sends private no-store plus CSP sandbox (`EvidencePreviewController.java:11-24`).
- Health exposure includes only actuator health (`application.yml:76-83`); compose healthcheck probes `/actuator/health` (`compose.yaml:87-89`).
- Import is operational CLI, not an HTTP endpoint. `scripts/pipeline/run_science.py` prepares/executes scientific imports through `viridexa_importer`; course extract import is in `scripts/pipeline/import_course_extracts.py`. Importer DB role has SELECT and narrowly granted INSERT per initialization/provisioning scripts; application API exposes no import controller. Treat CLI execution and protected source access as operator-only.

## Risks and follow-up

1. Deployment must set the real `WEB_ORIGIN` and secure session cookie. CORS credentials are disabled, so cross-origin cookie-based UI requests will fail unless same-origin proxying is used; wildcard origins are not configured. Local compose defaults Turnstile off; production compose requires real keys and exact hostnames.
2. In-memory account throttling and local-file agent quotas are per-process. Horizontal replicas multiply effective limits and quota state can diverge; use shared enforcement/storage if scaling beyond one API instance.
3. Database query-timeout coverage is mixed: MyBatis has 5s, account and review JDBC have 8s, and selected graph/workbench transaction scopes have 10s. General read-only JDBC has a 5s template timeout and a real MySQL timeout/reuse test.
4. Public scientific routes and identification inputs have less visible controller-level validation than plant and agent inputs. Confirm service-level max limits and add request bounds where absent; keep public result caps and indexes aligned.
5. Admin preview is bounded by type/size and hash verification. Validate protected-root containment and symlink handling in `EvidenceIntegrity` as part of deployment review.
